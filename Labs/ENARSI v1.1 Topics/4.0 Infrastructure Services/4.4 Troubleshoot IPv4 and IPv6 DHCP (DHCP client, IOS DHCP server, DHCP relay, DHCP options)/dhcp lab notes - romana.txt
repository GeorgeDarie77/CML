Nu, pe Cisco IOS nu poți defini mai multe comenzi host în interiorul aceluiași ip dhcp pool. 
Dacă introduci o a doua comandă host sau un al doilea client-identifier în același pool, comanda nouă o va suprascrie pur și simplu pe cea anterioară.
Din cauza modului în care este concepută arhitectura serverului DHCP din Cisco IOS, fiecare rezervare statică necesită propriul său ip dhcp pool separat.

De ce nu funcționează într-un singur pool?

• Relație 1-la-1: În Cisco IOS, un pool DHCP de tip manual (host) mapează o singură adresă IP la un singur identificator (client-identifier sau hardware-address).
• Suprascriere automată: Dacă rulezi host 172.16.99.2 și apoi host 172.16.99.3 în același pool, routerul va păstra doar ultima valoare (172.16.99.3).

Alternativa pe Cisco IOS (dacă ai multe rezervări statice)

Dacă ai zeci de dispozitive și nu vrei să încarci configurația routerului cu câte un bloc ip dhcp pool pentru fiecare în parte, singura modalitate de a grupa toate rezervările într-un singur loc pe Cisco IOS este fișierul text de tip DHCP Static Binding Database (stocat în flash: sau pe un server TFTP).

Cum funcționează metoda cu fișier text:

1. Creezi un fișier text (ex. static-bindings.txt) cu toate mapările IP – Client ID pe linii separate:
text
*time* Infinite
!IP address       Type    Hardware address     Lease expiration
172.16.99.2 /24   id      0108.0027.4b1c.9a    Infinite
172.16.99.3 /24   id      0108.0027.4111.9b    Infinite
*end*
Use code with caution.
2. Încarci fișierul în flash: pe router și indici serverului DHCP să citească rezervările din el folosind un pool de tip origin file:
cisco
CE(config)# ip dhcp pool STATICE_FISIER
CE(dhcp-config)# origin file flash:static-bindings.txt
CE(dhcp-config)# exit
Use code with caution.

Ce variantă merită să alegi?

• Sub 15–20 de dispozitive: Folosește pool-uri separate (ip dhcp pool STATIC_1, STATIC_2 etc.). Este mult mai ușor de depanat, nu depinde de fișiere externe din flash și se vede direct în show running-config.
• Peste 20–30 de dispozitive: Folosește metoda cu fișierul text (origin file), pentru a păstra configurația routerului curată.
(Notă: În exemplul tău apare 172.16.19.3 în loc de 172.16.99.3 și 0108.002. cu 3 cifre în loc de 4 — asigură-te că păstrezi subrețeaua 172.16.99.x și formatul cu câte 4 caractere hexazecimale separate prin punct, ex. 0108.0027.4111.9b.)


Varianta cu fișier în flash: (origin file) este un exercițiu excelent pentru laborator, deoarece folosește același format ca mecanismul de DHCP Database Agent din Cisco IOS.
Pe Cisco IOS nu există un editor de text clasic (precum nano sau vim), așa că cea mai rapidă și curată metodă de a crea un fișier direct în memoria flash: fără un server TFTP extern este folosirea TCL Shell (tclsh), integrat nativ în IOS.

Pasul 1: Verifică spațiul și conținutul memoriei Flash

Înainte de a crea fișierul, verifică numele exact al sistemului de fișiere (flash:, bootflash: etc.) și spațiul disponibil.
cisco
CE# dir flash:
(Dacă comanda returnează eroare, rulează show file systems pentru a vedea denumirea exactă a memoriei flash de pe modelul tău de router).

Pasul 2: Creează fișierul static-bindings.txt în flash: folosind TCL

Intră în modul tclsh și scrie fișierul direct pe flash. Structura fișierului trebuie respectată strict (antetul *time*, coloanele și finalul *end*).
cisco
CE# tclsh
CE(tcl)# puts [open "flash:static-bindings.txt" w+] {
*time* Infinite
!IP address       Type    Hardware address     Lease expiration
172.16.99.2 /24   id      0108.0027.4b1c.9a    Infinite
172.16.99.3 /24   id      0108.0027.4111.9b    Infinite
172.16.99.4 /24   id      0108.0027.5222.9c    Infinite
*end*
}
CE(tcl)# tclquit

Reguli critice pentru formatul fișierului:

• *time* Infinite și *end*: Sunt obligatorii; fără ele, parser-ul DHCP din Cisco IOS ignoră fișierul.
• Coloana Type: Folosește id atunci când pui prefixul 01 în fața adresei MAC (pentru client-identifier), sau hw dacă pui adresa MAC simplă fără 01 (ex. 0800.274b.1c9a).
• Spațierea: Separă coloanele prin spații sau tab-uri, exact ca în exemplul de mai sus.

Pasul 3: Verifică fișierul creat în flash:

Asigură-te că fișierul există și nu conține caractere lipsă sau erori de sintaxă.
cisco

CE# more flash:static-bindings.txt
Use code with caution.

Acum leagă fișierul de un pool DHCP dedicat. Pool-ul cu origin file va prelua automat setările de rețea (default-router, dns-server) din pool-ul părinte (POOL_DINAMIC), dacă acesta există.

CE(dhcp-config)# network 172.16.99.0 255.255.255.0
CE(dhcp-config)# default-router 172.16.99.1
CE(dhcp-config)# dns-server 8.8.8.8 1.1.1.1
CE(dhcp-config)# exit

! 3. Pool-ul static care citește din fișierul din flash
CE(config)# ip dhcp pool STATICE_FLASH

Si care e comanda de modificare a fisieruui?

Pe Cisco IOS nu există o comandă nativă de editare interactivă (precum nano sau vi), dar poți modifica fișierul în trei moduri practice, în funcție de ce vrei să faci:

1. Suprascrierea completă din tclsh (cea mai simplă pentru câteva linii)

Deoarece modul w+ din TCL șterge automat conținutul vechi și îl scrie pe cel nou, cea mai rapidă metodă de „editare” este să copiezi conținutul cu more flash:static-bindings.txt, să îl modifici într-un Notepad pe calculator și să îl lipești din nou în tclsh:
cisco
CE# tclsh
CE(tcl)# puts [open "flash0:static-bindings.txt" w+] {
*version* 2
*time* Infinite
!IP address       Type    Hardware address     Lease expiration
172.16.99.2 /24       id      0152.5400.d06d.25    Infinite
172.16.99.3 /24       hw      0152.5400.056b.22    Infinite
172.16.99.4 /24       id      0152.5400.b13a.e1    Infinite
*end*
}
CE(tcl)# tclquit
52:54:00:d0:6d:25
52:54:00:05:6b:22
52:54:00:b1:3a:e1

2. Modificarea punctuală din tclsh (înlocuire text cu regsub)

Dacă ai un fișier mai mare și vrei să schimbi doar o adresă IP sau un MAC fără să rescrii tot fișierul, poți citi conținutul într-o variabilă TCL, îl modifici cu regsub și îl salvezi la loc:
cisco
CE# tclsh
CE(tcl)# set f [open "flash:static-bindings.txt" r]
CE(tcl)# set continut [read $f]
CE(tcl)# close $f
CE(tcl)# regsub -all {172\.16\.99\.4} $continut {172.16.99.10} continut_nou
CE(tcl)# set f [open "flash:static-bindings.txt" w+]
CE(tcl)# puts -nonewline $f $continut_nou
CE(tcl)# close $f
CE(tcl)# tclquit
Use code with caution.
(Notă: În regsub, punctele din adresa IP trebuie precedate de \ deoarece sunt tratate ca expresii regulate).

3. Editare pe PC și transfer prin TFTP / SCP (pentru fișiere mari)

În mediile de producție, fișierul se editează pe un calculator și se suprascrie pe router prin rețea:
cisco
CE# copy tftp://172.16.99.100/static-bindings.txt flash:static-bindings.txt
Use code with caution.
(Routerul te va întreba dacă vrei să suprascrii fișierul existent — confirmi cu Enter).

Pas obligatoriu după orice modificare!

Indiferent de metoda prin care modifici fișierul în flash:, routerul nu recitește automat fișierul în timp real. Trebuie să îl forțezi să reîncarce baza de date DHCP:
cisco
CE# configure terminal
CE(config)# no service dhcp
CE(config)# service dhcp
CE(config)# end
CE# show ip dhcp binding

allow dhcp static allocation
To set up DHCP static allocation (also called a DHCP reservation), keep the Ubuntu machine set to receive its IP automatically via DHCP and bind its MAC address to a specific IP address on your router or DHCP server. This ensures the server always assigns the exact same IP address to that machine without you having to hardcode a static IP on Ubuntu itself.
Step 1: Find the MAC Address on Ubuntu
Your DHCP server uses your network interface's hardware (MAC) address to recognize the machine.
Run the interface check command. Open a terminal on your Ubuntu machine and run ip link show (or ip a).
Locate your active interface. Find your network adapter (e.g., enp0s3 or eth0).
Copy the MAC address. Look for the link/ether line and note the 6-pair hexadecimal address next to it (for example, 08:00:27:4b:1c:9a).
Step 2: Configure the Reservation on Your DHCP Server
How you apply the reservation depends on what device or software manages DHCP on your network.
Option A: Home or Office Router
Most consumer and small-business routers manage DHCP through a web interface.
Log into your router. Open a browser and navigate to your router's gateway IP (commonly 192.168.1.1 or 192.168.0.1).
Find the DHCP reservation menu. Look under LAN Settings, DHCP Server, or Address Reservation.
Add a new entry. Enter the Ubuntu machine's MAC address, the desired IP address (make sure it is inside your subnet, such as 192.168.1.50), and a recognizable hostname.
Save and reboot if prompted. Apply the router settings so the reservation becomes active.
Option B: Linux DHCP Server (isc-dhcp-server or kea-dhcp4)
If another Linux server on your network acts as the DHCP server, add a host block to its configuration.
For isc-dhcp-server: Edit /etc/dhcp/dhcpd.conf and add a host declaration, then restart the service with sudo systemctl restart isc-dhcp-server.
text
host ubuntu-machine {
  hardware ethernet 08:00:27:4b:1c:9a;
  fixed-address 192.168.1.50;
}
Use code with caution.
For Kea DHCP (kea-dhcp4): Edit /etc/kea/kea-dhcp4.conf inside your subnet4 block under reservations, then restart with sudo systemctl restart kea-dhcp4-server.
json
"reservations": [
  {
    "hw-address": "08:00:27:4b:1c:9a",
    "ip-address": "192.168.1.50"
  }
]
Use code with caution.
Step 3: Renew the DHCP Lease on Ubuntu
Once the reservation is saved on the server, force Ubuntu to request the newly assigned IP address.
Ensure Ubuntu is still using DHCP. Confirm that dhcp4: true is set in /etc/netplan/*.yaml (and no manual static IP is overriding it).
Apply Netplan or renew the lease. Run sudo netplan apply or renew the lease directly using sudo dhclient -r && sudo dhclient.
Verify the reserved IP. Run ip addr show to confirm the interface now holds the exact IP address you reserved.
(Note: If you use cloud-init or virtualized environments like VMware/VirtualBox, Ubuntu sometimes sends a client-id instead of its MAC address by default. If the reservation is ignored, add dhcp-identifier: mac directly under dhcp4: true in your Netplan file and run sudo netplan apply.)

in CLI
Pentru a configura alocarea statică DHCP (rezervare pe bază de adresă MAC) din linia de comandă (CLI), comenzile diferă în funcție de sistemul de operare al routerului. Mai jos sunt comenzile exacte pentru cele mai utilizate sisteme de routere configurabile prin SSH / Telnet / Consolă.
(Notă: În exemplele de mai jos, folosim IP-ul dorit 192.168.1.50 și adresa MAC 08:00:27:4b:1c:9a.)
1. Cisco IOS / IOS-XE
Pe routerele Cisco, se creează un DHCP pool separat dedicat exclusiv acelui client (identificat prin client-identifier sau hardware-address).
cisco
enable
configure terminal
ip dhcp pool UBUNTU_STATIC
   host 192.168.1.50 255.255.255.0
   client-identifier 0108.0027.4b1c.9a
   default-router 192.168.1.1
   dns-server 8.8.8.8 1.1.1.1
end
write memory
Use code with caution.
(Notă: La client-identifier pe Cisco, se adaugă prefixul 01 — care indică Ethernet — urmat de adresa MAC scrisă în grupuri de câte 4 caractere separate prin punct).
2. MikroTik (RouterOS)
Pe MikroTik, poți fie să transformi un lease existent în unul static, fie să adaugi direct o intrare nouă în lista de lease-uri.
routeros
/ip dhcp-server lease add address=192.168.1.50 mac-address=08:00:27:4B:1C:9A server=dhcp1 comment="Ubuntu-Server"
Use code with caution.
(Verifică numele serverului DHCP folosind comanda /ip dhcp-server print, dacă nu este dhcp1.)
3. OpenWrt / Linux Router (uci / dnsmasq)
Pe routerele cu OpenWrt, rezervările se configurează prin sistemul uci (care modifică /etc/config/dhcp).
bash
uci add dhcp host
uci set dhcp.@host[-1].name='ubuntu-server'
uci set dhcp.@host[-1].mac='08:00:27:4b:1c:9a'
uci set dhcp.@host[-1].ip='192.168.1.50'
uci commit dhcp
/etc/init.d/dnsmasq restart
Use code with caution.
4. VyOS / EdgeOS (Ubiquiti EdgeRouter)
Pe sistemele bazate pe VyOS (inclusiv EdgeRouter), rezervarea se adaugă în subrețeaua serviciului DHCP.
bash
configure
set service dhcp-server shared-network-name LAN subnet 192.168.1.0/24 static-mapping ubuntu-server ip-address 192.168.1.50
set service dhcp-server shared-network-name LAN subnet 192.168.1.0/24 static-mapping ubuntu-server mac-address 08:00:27:4b:1c:9a
commit
save
exit
Use code with caution.
5. FortiGate (FortiOS)
Pe firewall-urile/routerele FortiGate, rezervarea se adaugă în lista reserved-address a serverului DHCP de pe interfața LAN.
fortios
config system dhcp server
    edit 1
        config reserved-address
            edit 0
                set ip 192.168.1.50
                set mac 08:00:27:4b:1c:9a
                set description "Ubuntu-Server"
            next
        end
    next
end
Use code with caution.
